## 一、算法架构总览

系统包含两套独立的预测/分析算法：

**算法 A：负荷预测（主预测链路）**
- 文件：`src/prediction/load_forecast.py`
- 两阶段架构：**日总量预测**（自适应窗口 + 季节分解）→ **逐时分配**（KNN 模板匹配）
- 支持排班日历修正 + 天气预报修正
- 用于：预测未来 N 天逐时负荷

**算法 B：相似日分析（辅助分析链路）**
- 文件：`src/similarity/similar_day.py`
- 6 因子加权混合距离匹配
- 基于 Z-Score 标准化 + 数值连续距离 + 离散因子得分
- 用于：找历史上天气最相似的日子，辅助判断预测合理性

## 二、算法 A 详细说明：负荷预测

### 2.1 阶段一：日总量预测 (`forecast_daily_adaptive`)

**原理**：自适应窗口均值 + 周季节性分解 + 均值回归 + 天气/日历修正

**步骤：**

1. **分解周季节性**：计算每周 7 天的日均偏差 `seasonal[dow]`
2. **去季节化**：`deseasoned[t] = y[t] - seasonal[dow[t]]`
3. **网格搜索最优参数**：遍历窗口长度 `[14, 21, 28, 42, 56]` × 回归强度 `[0, 0.2, 0.4, 0.6]`，在验证集（最后 30 天）上选 MAE 最小的 `(window, reg)` 组合
4. **基预测**：`base = mean(deseasoned[-best_window:])`
5. **均值回归修正**：`deviation = base - all_mean`，乘以 `(1 - reg)` 拉回均值
6. **加回周季节性**：`forecast[date] = base + seasonal[dayofweek]`
7. **日历修正**（如启用）：预测值 × `day_type_weight`（生产日 1.0 / 休息日 0.7 / 节假日 0.4）
8. **天气修正**（如启用）：
   - 高温（日均 > 35°C）：**×1.03**
   - 低温（日均 < 5°C）：**×1.02**
   - 暴雨（日降水 > 10mm）：**×0.98**
9. **置信区间**：80% CI = `forecast ± 1.28 × residual_std`

**关键参数：**

| 参数 | 默认值 |
|------|--------|
| 窗口搜索范围 | [14, 21, 28, 42, 56] 天 |
| 回归强度搜索 | [0, 0.2, 0.4, 0.6] |
| 最小窗口 | 14 天 |
| 验证集 | 最后 30 天 |
| 高温阈值 / 因子 | 35°C / ×1.03 |
| 低温阈值 / 因子 | 5°C / ×1.02 |
| 暴雨阈值 / 因子 | 10mm / ×0.98 |
| 置信区间 z 值 | 1.28（80% CI） |

### 2.2 阶段二：逐时分配 (`generate_hourly_forecast`)

**原理**：KNN 模板匹配 + 加权平均 + 辐照修正

**步骤：**

1. **构建模板库**：从历史逐时数据提取每条记录 `{date, daily_total, hourly_profile(24维归一化), day_type}`
2. 对每个预测日：
   - a. 确定日类型（优先日历 > 工作日推断）
   - b. 在同 `day_type` 模板中，按日总量距离排序，取 **Top-K（K=5）**
   - c. **距离加权平均**：`weight = 1 / (|daily_total_diff| + 0.001)`，归一化后加权合并 24h profile
   - d. **辐照修正**（如有预报辐照）：中午 10-15h 下调负荷（光伏替代效应），最大下调 5%
   - e. `daily_total × profile[h]` → 逐时负荷
3. 输出每条记录：`datetime, hour, load_mw, daily_total_mwh, profile_std_mw, matched_dates`

**关键参数：**

| 参数 | 默认值 |
|------|--------|
| KNN K 值 | 5 |
| 辐照最大下调 | 5% |
| 中午核心小时 | 11-14h（下调 50%） |
| 中午边缘小时 | 10h / 15h（下调 25%） |
| 辐照参考值 | 5000 W/m² |

### 2.3 模板匹配细节 (`match_templates`)

- **优先级策略**：同 `day_type` 内匹配 → 同类不足 3 个时放宽到"非节假日" → 仍不足则使用全部天
- **权重**：日总量越接近的历史天权重越大（反比于距离）
- **输出**：加权逐时曲线 + 匹配日期列表（用于可解释性）

## 三、算法 B 详细说明：相似日分析

### 3.1 算法原理

基于 6 因子加权距离，从历史天气数据中找出与目标日气象条件最相似的日子。

### 3.2 6 因子权重

基于 395 天工业负荷与天气变量的相关性分析标定：

| 因子 | 权重 | 类型 | 数据依据 |
|------|:---:|------|----------|
| 最低温偏差 (tmin) | **0.25** | 数值 | 与负荷 r = 0.694 |
| 最高温偏差 (tmax) | **0.20** | 数值 | 与负荷 r = 0.569 |
| 降水匹配 (precip) | **0.18** | 混合 | 连续 + 等级 |
| 季节匹配 (season) | **0.12** | 离散 | 秋 0.76 / 冬 -0.23 |
| 日期距离衰减 | **0.10** | 衰减 | 90 天后指数衰减 |
| 露点偏差 (dew_point) | **0.10** | 数值 | 与负荷 r = 0.673 |
| 星期匹配 | **0.05** | 离散 | 工业负荷星期效应仅 0.7% |

### 3.3 计算流程

1. **逐时 → 逐日聚合**：tmax, tmin, precip_sum, rad_daily_sum, dew_point_avg
2. **晴雨硬约束**：目标日为降水日（≥ 0.5mm）时，候选项必须 ≥ 0.3mm（≥ 10 个候选项则执行）
3. **Z-Score 标准化**：对数值因子（tmax / tmin / rad / dew_point）学习历史 mean / std
4. **混合距离计算**：
   - 数值因子：**5 × |z_diff| × 权重**（曼哈顿距离）
   - 降水：对数压缩连续距离（70%）+ 等级差异（30%）
   - 季节：同季 = 0，相邻 = 0.5，相反 = 1
   - 星期：同类型 = 0，不同类型 = 1
   - 日期距离：90 天内 = 0，之后指数衰减，半衰期 180 天
5. **排序 + 指数相似度转换**：`similarity_pct = 100 × e^(-d/σ)`，σ = 距离中位数
6. 返回 **Top-N**（默认 3）

## 四、排班日历系统

- **文件**：`src/prediction/calendar.py`
- **默认规则**：周一至周五 = 生产日（weight 1.0），周六日 = 休息日（0.7）
- **扩展能力**：支持用户上传自定义日历（Excel/CSV），可标记节假日（0.4）
- **作用位置**：
  - **日总量预测**：乘以 `day_type_weight` 直接缩放预测值
  - **模板匹配**：限定在同 `day_type` 内搜索匹配

## 五、天气因素参与方式总结

| 天气因素 | 参与环节 | 具体方式 |
|----------|----------|----------|
| 温度（tmax / tmin） | 日总量修正 | > 35°C + 3%，< 5°C + 2% |
| 降水量 | 日总量修正 | > 10mm - 2% |
| 辐射量 | 逐时分配修正 | 午间 10-15 时下调，最大 5% |
| 温度 / 降水 / 辐射 / 露点 | 相似日分析 | 6 因子加权距离 |
| 季节 | 相似日分析 | 同季节优先匹配 |
| 湿度 / 风速 / 云量 | 相似日分析 | 作为距离因子参与计算 |
