# 污水处理厂7月负荷预测 — 改进方案设计

## 问题诊断

当前模型（XGBoost + Prophet 集成，递归逐时预测）在 A公司的表现：

| 指标 | 6月验证集 | 7月实际 |
|------|----------|--------|
| MAE (逐时) | 0.59 MW | 0.79 MW |
| MAPE (日总) | — | 13.84% |
| R² | 0.73 | 0.47 |

**根因分析：**

1. **趋势外推过度**：模型训练期（4-6月）日均从 126.7→121.0→109.0→96.2（最后一周）持续下降，递归预测从最低点出发被锚定在低位，预测 98.8 MWh/天，但 7月实际反弹到 104.4。
2. **递归误差累积**：XGBoost 用自身预测值作为 lag 特征，起始于 6月底低谷，恢复速度远慢于现实。
3. **逐时预测噪声大**：直接用 lag_24h/lag_168h 等特征预测逐时负荷，日总量层面的系统性偏差无法被纠正。
4. **A公司变异系数最大**（CV=12.6% vs B=10.2% vs C=7.3%），却被当作与其他公司同质的时序处理。

## 改进方案：两阶段解耦预测

### 阶段一：日总量预测（Holt-Winters 指数平滑 + Damped Trend）

**为什么选 Holt-Winters：**
- 自带趋势阻尼（damped trend），当数据持续下降时，预测不会无限外推下降趋势，而是逐渐向长期均值回归
- 显式建模周季节性（7天周期）
- 参数少、可解释、不会像 XGBoost 那样被最后一周的数据锚定
- 输出预测方差，可以构建置信区间

**实现细节：**
- 使用 `statsmodels.tsa.holtwinters.ExponentialSmoothing`
- 趋势成分：damped（关键改进点）
- 季节成分：additive，周期=7天
- 对每家公司独立拟合，自动选择最优平滑参数
- 输出：31天日总量点预测 + 80%预测区间

### 阶段二：逐时分配（KNN 历史模板匹配）

**为什么选模板匹配：**
- 污水处理厂的逐时负荷形态相对稳定（白天低、早晚高），主要变异来自日总量
- 日总量接近的历史天，其逐时分配模式也相似
- 避免递归预测的误差累积
- 按工作日/周末分开匹配，保留周内模式差异

**实现细节：**
- 对每个预测日：
  1. 确定是工作日还是周末
  2. 在对应类型的历史天中，找日总量最接近的 K=5 天
  3. 对 K 个模板的逐时归一化曲线取加权平均（权重=1/|日总量差|）
  4. 将日总量预测值 × 归一化分配曲线 → 逐时负荷
- 不确定性：日总量预测区间 × 分配曲线的历史波动范围

### 阶段三：模型对比与输出

- 新方法：Holt-Winters(日总) + KNN(分配)
- 旧方法（保留作为 baseline）：XGBoost + Prophet 集成
- 评估指标：MAE、RMSE、MAPE、R²，分日总量和逐时两级
- 输出 Excel：与现有格式一致，新增方法占主导，旧方法保留对照
- 新增预测区间列（P10/P50/P90）

## 验证策略

1. **回测验证**：在 4-6月数据上做滚动窗口验证（用4-5月训、6月测），对比新旧方法
2. **7月实际验证**：用实际7月数据计算真实 MAE/MAPE
3. **成功标准**：A公司日总 MAPE < 8%（当前 13.84%），逐时 MAE < 0.5 MW（当前 0.79）

## 实际结果 (2026-07-29)

经过 5 轮迭代，最终方案为**自适应窗口 + 周季节性 + 均值回归**日总量预测 + **KNN 模板匹配**逐时分配。

| 公司 | 指标 | 旧方法 | 新方法 | 变化 |
|------|------|--------|--------|------|
| A公司 | 日总 MAPE | 13.84% | 13.80% | -0.3% |
| A公司 | 逐时 MAE | 0.79 MW | 0.82 MW | +4.6% |
| B公司 | 日总 MAPE | 25.70% | 17.35% | -32.5% |
| B公司 | 逐时 MAE | 0.56 MW | 0.41 MW | -27.5% |
| C公司 | 日总 MAPE | 4.82% | 4.93% | +2.5% |
| C公司 | 逐时 MAE | 0.04 MW | 0.04 MW | 持平 |

**结论：**
- B公司大幅改善（自适应窗口降低了对短期波动的过拟合）
- A公司基本持平：日均接近实际（98.4 vs 104.4），但每日波动（std=14.9 MWh）无法从历史数据预测
- 午间误差是其他时段 2.4 倍（A公司），确认光伏/天气是主要未建模因素
- **需要一年数据 + 天气/光伏特征才能根本性提升 A公司精度**
- 建议下一步：获取数据后做碳核算 + 优化调度流程，负荷预测作为在线修正模块持续迭代
